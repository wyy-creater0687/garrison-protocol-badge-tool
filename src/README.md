# src —— 行为重建（非原码）

原程序是闭源打包的 Python 字节码，这里放的是**按反汇编人工翻译/重建**的源码，
用于理解它的局内逻辑。注意：这不是原作者源码，个别细节（尤其是坐标常量和
OCR 区域）是按反汇编推断的。

| 文件 | 内容 | 可信度 |
|---|---|---|
| `prep_phase.py` | 回合准备阶段：升级商店、买干员、部署、点准备就绪 | **逐条翻译**（变量名、字符串、比较方向、循环次数与反汇编一致） |
| `main_loop.py` | 主循环：界面导航、局内回合、结算统计、超时保护 | **结构级重建**（分支关键字与日志取自反汇编，细节被抽象成辅助函数） |

## 回合准备阶段在做什么

1. 读商店（资金 / 升级费用 / 是否满级 / 回合号）；
2. **第 1 回合只买 2 个干员**，且最多 1 个医疗；
3. **升级商店**：钱够就点升级，最多 4 次；每次点完都用「资金变了 / 升级费用降了 /
   按钮位置变了」来确认真的升上去了，没变化就停，避免死循环；
4. 没满级时继续买，**每买一个都重新截图**确认资金和部署位；
5. 满级后**刷新找 5/6 级干员**，选择顺序是：
   优先表里的 → 已经拥有的（凑同名晋升）→ 输出位 → 随便；
   连续两次刷新商店没变化就判定「刷不动了」，存图并停止刷新；
6. 有备战席干员时先部署，再点「准备就绪」，最后关掉可能弹出的提示框。

## 局内为什么这样买人

- 第 1 回合买 2 个、其余钱升级商店 → 第 4~5 回合就能满级；
- 满级后商店只出 5/6 级干员，按权重表优先买；
- 已经拥有的干员优先买（凑同名晋升，星级会涨）；
- 不买装备（原程序没有装备相关逻辑）。

## 超时与保护

| 常量 | 值 | 作用 |
|---|---|---|
| `LEAVE_TIMEOUT` | 180 秒（原版 30） | 这么久看不到卫戍协议界面就停止 |
| `STALL_TIMEOUT` | 600 秒 | 局内没有进展判定卡死 |
| 刷新上限 | 40 轮 | 满级后刷商店的循环上限 |
| 升级上限 | 4 次 | 每次准备最多点几次升级 |
